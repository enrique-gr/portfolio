VTOL-01 Sensor Dropouts on Bench Test ✓ RESOLVED
Project WashU VTOL
Domain Embedded / Avionics
Protocol I2C
Symptom

During bench testing with motors spinning, the Pixhawk 6C was intermittently losing telemetry from I2C sensors — barometer and magnetometer dropouts occurring inconsistently, with no pattern tied to throttle level or duration.

Root Cause

Electrical noise from the motor power wiring was coupling onto the I2C signal lines through proximity and insufficient shielding. The I2C bus is particularly susceptible to this — the long pull-up rise times make the logic edges soft and easy to corrupt under EMI. The unshielded sense lines were routed parallel to the high-current motor runs for about 15 cm.

Resolution
Re-routed all avionics signal wiring away from motor power runs and added twisted-pair shielding on the I2C lines. Also added hardware pull-up resistors (2.2 kΩ) to tighten rise times. Sensor dropout issue did not recur across subsequent bench tests.
HYPERION-01 Thread Contention Jitter in Physics Loop ✓ RESOLVED
Project Hyperion 6-DOF Engine
Domain Concurrent C++
Symptom Type Timing jitter
Symptom

The physics integration loop was running at a nominal 10 kHz, but profiling showed irregular step intervals — some steps taking 2–3× longer than expected. This was introducing integration error that caused the simulated trajectory to drift from analytical benchmarks.

Root Cause

The physics thread and the telemetry logging thread were both acquiring the same mutex to access shared state. When the logger thread held the lock, the physics thread blocked and missed its timing window. Since the logger ran on no fixed schedule, the block duration was unpredictable.

Resolution
Replaced the shared-mutex pattern with a double-buffered state handoff. The physics thread writes to one buffer while the logger reads from the other; a single atomic pointer swap transfers ownership with no blocking. Integration jitter dropped to within timing resolution, and the trajectory now tracks analytical benchmarks within acceptable tolerance.
PROP-09 Igniter Continuity False Positive ✓ RESOLVED
Project Propulsion Test Stand
Domain Embedded / Safety Systems
Symptom Type ADC false read
Symptom

The igniter continuity check was reporting "continuity present" even with no igniter connected. This was a safety-critical false positive — the system would have allowed a fire command believing the igniter circuit was intact.

Root Cause

The ADC sense pin was left floating when no igniter was connected. The MCU's internal pull-up was insufficient to hold the pin cleanly low — the floating voltage settled in the threshold region and was inconsistently interpreted as logic high by the firmware.

Resolution
Added a hardware pulldown resistor (10 kΩ) on the sense pin to ensure a clean logic-low default. Also added software debounce logic requiring five consecutive consistent reads before reporting continuity state, eliminating transient misreads. False positive did not recur.
DBF-01 Pitch Stability Hunting in Flight ✓ RESOLVED
Project WashU Design/Build/Fly
Domain Aerodynamics / Stability
Symptom Type Longitudinal instability
Symptom

The aircraft exhibited persistent pitch oscillation in flight — a phugoid-like hunting around the trim pitch angle rather than converging to steady level flight. This was degrading payload mission accuracy.

Root Cause

CG had shifted aft from the design position due to battery placement during final assembly. The reduced static margin pushed the aircraft toward neutral stability — any pitch perturbation was not being restored by the tail, causing the oscillation instead of damping it.

Resolution
Shifted battery pack forward to recover static margin. Also increased horizontal tail chord to improve pitch authority and damping. Aircraft demonstrated stable pitch response in subsequent flight tests.
